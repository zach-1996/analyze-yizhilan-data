# 业务语义与数据完整性

## 语义判断

采用“受控语义理解”：结合用户完整表达、当前指标字典和上下文判断，不要求机械字符串相等，也不得把相近词随意归并。

| 用户表达 | 规范理解 | 禁止替代 |
|---|---|---|
| 招生点数 | 招生点数；营业额的替代指标，1 个点对应 15,000 元学费收入 | 招生人数、报名量 |
| 招生人数 | 报名量；输出时必须写“招生人数（报名量）” | 招生点数、总报名量（含预报）、当月信息报名量 |
| 线索 | 信息池信息 | 有效信息 |
| 信息 | 有效信息 | 信息池信息 |
| 点均成本 | 招生点相关的点均成本 | 生均成本、有效信息成本 |
| 费率 | 点均成本 / 15,000；百分比展示时乘以 100% | 生均成本率、信息成本率 |
| 生均成本 | 招生人数/报名相关的生均成本 | 点均成本 |
| 上门成本、报名成本、点均成本 | 后端转化成本；优先选择带“现金”限定词的对应指标，并保持与消耗、转化结果相同的渠道范围 | 未经确认的账面成本、其他相近成本 |
| MCP 原始指标编号/标签 | 仅作内部查询标识，必须映射为当前指标字典中的业务名称 | 直接向用户展示原始内部标签 |
| 总报名量（含预报） | 独立指标，保留“含预报” | 报名量 |
| 当月信息报名量 | 独立指标，保留“当月信息” | 报名量 |
| 渠道（作为范围词） | “渠道”分类中的“线下渠道” | 全部渠道、媒体 |
| 分渠道 | 按渠道维度完整拆分并逐项标注，包括线下渠道 | 仅线下渠道、排除线下渠道 |
| 分平台 | 按媒体维度拆分 | 按渠道维度拆分 |

始终保留指标限定词。若指标字典仍留下两个会实质改变结果的候选，再用一个小问题确认；否则直接查询。

## 渠道范围与指标命名

### 默认范围

- 对统一数据视图等支持渠道筛选的非定制报表，默认排除“渠道”分类中的“线下渠道”。此规则适用于信息、上门/到访、报名、招生点数、学校对比、排名、汇总、漏斗、同比和环比。
- “排除线下渠道”应按报表直接指标执行：先按“渠道”维度拉取直接的总有效信息量、上门量、报名量等字段，识别并排除渠道名称严格等于“线下渠道”的行，再汇总剩余行。不得把系统自带的“网络总有效信息量”“网络上门量”“网络报名量”等派生字段当作该报表筛选逻辑的替代，除非用户明确要求这些网络字段。
- 汇总前必须列出纳入与排除的渠道行，并做一次算术核对；尤其不能把“线下渠道”行的直接转化量混入非线下结果。非线下但消耗为 0 的渠道仍按“渠道不为线下渠道”保留；若据此计算投放成本，必须说明成本分母包含全部非线下消耗，而转化分子可能包含无消耗渠道。
- 非定制报表中的“总数据”“总招生”“总点数”仍使用排除线下渠道的默认范围，不能据此推断用户要求含线下数据。
- 依据服务返回的渠道分类识别“线下渠道”，不能仅凭消耗为 0 判断。无法可靠识别时询问用户。
- 本期和对比期必须采用相同渠道范围。
- 通过 `unify_spec_report_run` 拉取定制报表时，按报表自身配置和返回数据取数，不额外设置“排除线下渠道”条件，也不强行追加网络口径查询；只有用户明确要求按渠道筛选且报表 schema 支持时才设置渠道条件。

### 明确包含线下

用户明确说“含渠道”“含线下”或同义表达时，对支持渠道筛选的非定制报表：

1. 同时查询含线下总口径和排除线下的网络口径。
2. 含线下指标使用普通名称：信息、上门/到访、报名、招生点数（点数）。
3. 不含线下指标使用“网络”前缀：网络信息、网络上门/网络到访、网络报名、网络招生点数（网络点数）。
4. 两套数据分列或分组展示，不把不同口径的分子、分母或变化量混在一起。

定制报表不因“含渠道/含线下”要求额外追加排除线下的网络查询；按定制报表原始口径直接取数，并说明实际渠道覆盖范围。

### 定制报表取数路径

- 根据用户指标、维度和报表语义匹配当前定制报表，优先选择能直接返回目标业务字段的同类报表。
- 当结果过大、截断或维度/分页/筛选不生效时，备用取数路径依次为：改用同类定制报表 → 减少字段 → 减少分组维度 → 拉完整列表后本地聚合。
- 报表字段画像只记录已验证的业务字段和行结构，运行时仍以当前目录和返回 schema 为准。
- 定制报表回答只说明本次返回实际包含的院校；未出现的院校不推断为 0。

### 媒体与拆分词

- “渠道”作为范围词时指“渠道”分类中的线下渠道；“分渠道”按渠道分类完整拆分并标注，包括线下渠道。
- “分平台”按媒体维度拆分；同时要求分平台、分渠道时分别展示两种维度。
- 用户明确点名的媒体优先于平台家族默认值；输出严格使用后台规范媒体名称。头条/字节平台默认集合为“巨量本地推”“抖音付费直播”“巨量引擎”“巨量本地推-直播”；快手平台默认集合为“快手”“快手付费直播”“快手本地推”。
- 用户要求平台合计、全包含或家族合计时才追加合计；分平台默认保留独立媒体行。合计按可加指标汇总，单位成本按合并分子/分母重算。

### 消耗与链路一致性

- 涉及消耗、成本、投放效率或从消耗开始的招生链路时，只使用网络口径：消耗 → 网络信息 → 网络上门/网络到访 → 网络报名 → 网络招生点数。
- 点均成本、生均成本和各阶段转化率只在同一网络口径内计算。禁止用线上消耗除以含线下的报名或招生点数。
- 用户要求“含渠道/含线下”时可以同时展示含线下结果，但这些结果不得接到线上消耗后计算成本或转化率。

### 用户指定的报表筛选逻辑

- 用户明确说“渠道不为线下渠道”或说明其后台操作是先筛选渠道再拉直接数据时，优先采用该报表逻辑：直接指标 + 渠道维度拆分 + 排除“线下渠道”行。
- 该逻辑下的正确聚合形式为：非线下总有效信息量、上门量、报名量分别对所有非线下渠道行求和；不得将非线下结果替换为网络限定字段。

## 动态指标字典

- 每个独立分析调用 company_metric_list 获取当前业务指标。
- 同一轮连续查询可复用已确认的字典结果。
- 不把 company_metric key 写入技能、绑定文件或长期记忆。
- 候选指标必须同时核对名称、定义、单位和限定词，不能只看相似度。
- 找不到同口径指标时明确说明，不用近似指标冒充。
- 对上门成本、报名成本、点均成本，先检查当前字典是否存在对应现金成本字段。存在时优先使用现金成本；不存在时检查同口径的现金消费/现金消耗字段，并按现金消费÷对应后端结果计算；只有两类现金字段都不存在时才报告字段缺失，不自动降级为账面成本，除非用户明确确认。
- MCP 返回的指标编号或内部标签不能直接写入用户答案；必须先映射为业务名称。若无法确认映射，则保留为“指标名称待确认”，不做成本归因。

## 日期解释

### 相对日期

- 按用户时区解释；未另行说明时使用当前会话时区。
- 对不涉及当日的任意时间周期，默认将结束日期设为前一天；只有用户明确要求“今天/当日/实时/截至当前时点”，或明确要求纳入当日，才查询当天数据。对于“本月/今年/截至目前”等相对周期，默认取周期开始日至前一天，并标注周期尚未结束。
- “最近 7 天”指今天之前的 7 个完整自然日，不含今天。
- 中文商业语境下，“周”默认周一至周日；用户或企业明确使用其他周定义时，以其定义为准。
- “本周/本月/今年”默认包含截至前一天的不完整周期，并明确标注“周期未结束”；只有明确要求当日或截至当前时点时才包含今天。
- 用户写出一个仍在进行中的绝对月份或年份时，名义区间仍是完整日历月/年，但实际查询默认截止前一天；未来日期不是 0。
- 未结束的本周做周环比时，本期从本周一截至前一天，对比期为上周一至上周对应的前一天；只有用户明确要求日内对齐时才纳入当日。
- “今年对去年”在今年未结束时默认采用今年截至前一天对上年同期；只有用户明确要求完整日历年时才比较完整年度。
- 数值查询没有日期时询问范围；仅为发现院校、媒体或指标对象时可使用工具当前快照，并披露实际周期。
- 服务快照工具以其返回的参考日期为准。

### 对比方式优先级

先判断用户是否要求比较：

- 用户只查询一个准确数值，且没有分析、表现、情况、变化、趋势、增长、下降、比较、对比或周期报告意图时，不强制增加对比期。
- 用户有上述任一意图时视为需要比较。若未明确对比方式或对比期，一律默认公历同比。

按以下顺序确定对比方式：

1. 用户明确指定对比日期或对比周期时，按指定区间执行；若指定区间与“同比/环比”标签冲突，先询问一次。
2. 用户同时明确要求同比和环比时，两种都查询并分开标注。
3. 用户明确说“农历同比”时，使用农历同比。
4. 用户明确说“环比”、日/周/月/季度环比，或明确要求与上一日、上周、上月、上季度、前一等长区间相比时，使用对应环比。
5. 用户明确说“同比”时使用公历同比；需要比较但没有明确方式时，也使用公历同比。

“本周”“本月”“本季度”“今年”“近 X 天”等只定义本期，不定义对比方式。不能因为出现这些相对周期就自动选择环比。

### 环比

只有用户明确要求环比，或明确指定上一相邻周期/日期作为对比期时，才使用本节规则。用户明确给出对比日期时，以用户指定为准。

按以下优先级确定对比期：

1. 用户明确给出的对比日期。
2. 用户明确说出的日环比、周环比、月环比或季度环比。
3. 用户只说“环比”时，按单个日期、明确日期区间或近 X 天的普通环比规则。

具体规则：

- 日环比：单个自然日对比前一天。
- 周环比：对比上一自然周的相同星期范围。完整周对比上一完整周；本周尚未结束时，本周一至当前日对比上周一至相同星期。
- 月环比：对比上一个自然月同期。完整自然月对比上一个完整自然月；本月尚未结束时，本月 1 日至当前日对比上月 1 日至相同日号。
- 季度环比：对比上一个自然季度同期。完整自然季度对比上一个完整自然季度；本季度尚未结束时，从本季度首日至当前日，对比上季度首日至相同季度内月序和日号。
- 单个明确日期只说“环比”：对比前一天。
- 明确日期区间只说“环比”：对比紧邻本期之前的等长自然日区间。
- 近 X 天环比：本期取今天之前的 X 个完整自然日，对比紧邻本期之前的 X 个完整自然日。

“明确日期区间”的普通环比不能覆盖用户明确说出的周期类型；只有只说“环比”时才对比前一个等长区间。

月环比或季度环比遇到上个自然周期没有相同日号时，先询问用户采用月末对齐还是另行指定等长区间，不擅自决定。完整自然月或完整自然季度直接对比上一个完整周期，不受天数不同影响。

### 公历同比

- 这是所有“需要比较但未明确对比方式”请求的默认方式，对比上一年相同公历日期区间。
- 本周、本月、本季度或今年尚未结束时，本期取截至服务参考时点的实际区间，对比上一年相同公历日期区间，并披露本期尚未结束。
- 2 月 29 日在上一年无对应日期时自动映射到 2 月 28 日，并披露对比期少一天或发生日期回退。
- 跨年同比遇到日期无法直接对齐时，按日期工具返回的可比区间执行，并在口径中说明对齐方式。

### 农历同比

只有用户明确说“农历同比”时使用：

1. 把本期每个边界日期换算为农历年、月、日和闰月标记。
2. 对比上一农历年的相同农历月日。
3. 再换算成公历查询区间。
4. 回答中同时写出本期和对比期的实际公历日期。
5. 若本期位于闰月而上一农历年不存在同一闰月，先询问用户如何对齐。
6. 若上一农历年对应月份不存在同一农历日，也先询问对齐方式。

优先运行 scripts/compare_dates.py 计算，不手工猜日期。脚本的 `current-week`、`current-month`、`current-quarter` 和 `recent-days` 模式默认计算公历同比；只有 `previous-period`、`day-over-day`、`week-over-week`、`month-over-month`、`quarter-over-quarter`、`current-week-over-week`、`current-month-over-month`、`current-quarter-over-quarter` 和 `recent-days-over-previous-period` 计算环比。

## 计算与聚合

- 服务已提供派生指标时优先使用服务值。
- 仅当派生指标不存在且公式明确时自行计算，并说明分子、分母、时间区间和空值处理。
- 成本派生指标的选择顺序为：同口径现金成本字段 → 同口径现金消费/现金消耗 ÷ 对应后端结果自行计算 → 用户明确确认的账面成本字段。计算时，上门成本=现金消费÷上门/到访量，报名成本=现金消费÷报名量，点均成本=现金消费÷招生点数。不得用信息成本、报名成本、生均成本或其他近似成本替代目标成本。
- 费率按“点均成本 / 15,000”计算；若以百分比展示，结果乘以 100%。点均成本、招生点数和费率必须保持同一网络/含线下口径，不能用生均成本或有效信息成本替代。
- 金额和数量只在维度互斥时求和。
- 比率、转化率、点击率、均价、单位成本等不能做简单平均；应使用基础分子与分母重新加权。
- 公式或基础字段不明确时不重新聚合。
- 不同时段、不同参考日期或不同口径的数据不能直接合并。

## 定制报表行语义

定制报表通常包含三类行：

- 明细：具体学校、渠道、项目或其他维度成员。
- 小计/合集：若干明细的合并，可能位于中间。
- 总计：通常在最后一行，但不能只凭位置判定。

识别时综合行标签、维度空白、“全部/合计/总计”等标记、层级关系和数值关系。不得把小计、总计与其下属明细再次相加。无法确定时保留服务原行标签并注明不确定性。

## 缺失、权限与新鲜度

- 数值 0：服务明确返回零。
- 空值：字段存在但没有值。
- 空结果：当前条件没有记录。
- 权限不足：账号不可见，不代表业务为零。
- 调用失败：没有取得可信结果。

回答前检查参考日期、更新时间、当日是否完整和账号可见范围。使用“基于当前账号可见数据”描述权限边界。

## 单位与变化

- 明确人民币/元、人数、点数、次数、百分比和百分点。
- 2% 到 3% 是增加 1 个百分点；相对变化率为 50%。两者含义不同。
- 涉及对比时，计数与金额默认给相对变化率；异常场景再补绝对变化。
