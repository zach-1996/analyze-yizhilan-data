# 分析与报告规范

## 分析深度

让查询深度与用户问题相称：

- 单点查询：返回准确数值、周期、结论和口径。
- 对比/排名：补充对比期、变化、基数和范围。
- 异常诊断：补充贡献拆解、底层验证和不确定性。
- 周报/月报：覆盖核心指标、主要增减、异常、归因、结论和可执行建议。

不要为了显得完整而扩大查询；也不要用一条汇总数据回答需要诊断的问题。

开始分析前先应用 references/business-semantics.md 的对比方式优先级。本文件中的“对比期”不代表默认环比：需要比较但未指定方式时使用公历同比，只有明确要求环比或明确指定上一相邻周期时才使用环比。

渠道范围统一遵循 `business-semantics.md`，本文件只负责分析和交付。

使用报表式“渠道不为线下渠道”口径时，先展示排除的“线下渠道”行和纳入的非线下渠道明细，再给出直接指标合计；交付前复核不能把线下行混入总量。

## 回答顺序

遵循 `../SKILL.md` 的“组织回答”和“输出底线”：简单查询先给结果，附周期与必要口径；复杂分析先给结论，再给证据、适用的行动建议和一次完整口径说明。驱动因素与异常属于数据证据，口径与限制不重复列出。

## 事实、推断、行动

- 事实：MCP 直接返回的数据、参考日期和服务明确标注的异常。
- 推断：由数据关系、拆分或服务摘要推导出的解释，注明证据强弱和替代解释。
- 行动：基于事实和推断提出的下一步，不写成已经发生的效果。

没有实验、明确业务事件或足够拆解证据时，使用“与……同步”“可能由……贡献”等表达，不写“由……导致”。

## 变化展示

### 数量与金额

涉及对比时默认列；单值查询只展示所查数值，不为补齐列而增加对比期：

- 本期值
- 对比期值
- 相对变化率

仅在以下情况增加绝对变化：

- 对比期为 0 或接近 0。
- 相对变化明显偏离同组分布。
- 变化率很大但绝对量很小。
- 服务标记异常。
- 绝对变化影响排名或核心结论。
- 用户明确要求。

不设置脱离业务规模的固定阈值。结合同行/同校分布、基数和业务重要性判断，并同时呈现相对变化与绝对变化，避免低基数放大变化率。

### 比率

涉及对比时，比率指标默认展示百分点变化；相对增幅只在有助于判断时补充。比率不能简单相加或平均。

## 归因

优先采用 MCP 明确给出的贡献度，但仍用底层数据核实。没有贡献度时，按互斥维度拆分本期和对比期：

- 区分“本期规模最大”和“对变化贡献最大”。
- 同时展示正向贡献和负向拖累。
- 给出已解释变化占总变化的覆盖度；未覆盖部分不得硬凑原因。
- 贡献和汇总方向不一致时检查小计重复、权限范围、空值和参考日期。

## 默认转化漏斗

默认漏斗顺序：

消耗 → 网络有效信息 → 网络到访 → 网络报名量（网络招生人数） → 网络招生点数

默认排除线下渠道，确保消耗与后续招生数据的范围一致。某一阶段没有同口径数据时保留缺口，不用近义指标补齐。点均成本与生均成本分别属于不同阶段，不得互换。

用户明确要求“含渠道/含线下”时，对非定制报表另行展示信息、上门/到访、报名和招生点数等含线下结果，同时保留对应的网络指标；定制报表按自身原始口径直接取数。含线下结果不接到线上消耗后计算成本或转化率。

## 异常判断

综合以下因素：

- 相对变化和绝对变化
- 对比期基数
- 对整体结果的重要性
- 数据完整性和当期是否结束
- 同组分布或历史范围
- 服务侧异常规则

AI 洞察摘要只是线索。必须尽可能回到底层指标验证，尤其是低基数、部分周期和权限不完整场景。

## 行动建议

每条建议包含：

1. 对象：学校、渠道、计划、素材或漏斗阶段。
2. 指标：建议针对的具体口径。
3. 动作：需要检查、试验或调整什么。
4. 预期方向：希望提升或降低什么。
5. 验证：用哪个指标、什么时间窗口复核。

技能只给建议，不直接调整业务配置。证据不足时建议先补查或做小范围验证。

## 输出模板

### 简单查询

- 结果：直接回答用户问题，给出关键值。
- 必要口径：统计周期、指标、渠道及对象范围、参考日期和完整性；仅涉及对比时补充对比日期与变化。

### 诊断分析

- 核心结论：最重要的 1–3 点。
- 数据证据：汇总、关键拆分、贡献、低基数、服务提示和底层验证。
- 行动建议：证据对应的验证或优化动作。
- 一次完整口径说明：统计周期与实际对比日期（适用时）、指标、渠道和对象范围、汇总或重算方式、分页、权限、完整性和不确定性。

### 周期报告

- 核心结论
- 数据证据：核心指标、主要增长与下降、异常与归因
- 行动建议
- 一次完整口径说明：周期与对比、指标、渠道和对象范围、汇总或重算方式、完整性与限制

## 表格和图表

- 表格默认只放关键行、小计和可信总计。用户明确要求“各/全部”对象时交付完整集合；过长则用分页或文件交付并在正文摘要关键行。
- 只展示前 N 时明确 N 和排序指标。
- 趋势、拐点或多周期对比确实需要时再画图。
- 不输出原始 JSON；完整明细需要分页或导出时先说明范围。

## 交付前检查

- 指标名称、限定词、成本口径和招生点数/报名量是否匹配？内部 key 是否已转换为后台规范名称？
- 渠道范围是否符合业务语义，且本期、对比期一致？消耗链路是否全程使用同一网络口径？
- 日期、同比/环比、参考时间和周期完整性是否正确？
- 若周期不涉及当日，结束日期是否已截到前一天？若使用直接指标筛选，是否排除了“线下渠道”行且没有混用“网络XXX”字段？
- 分页、截断、权限、空值/空结果/失败状态是否识别？Top N 是否明确范围？
- 明细、小计、总计是否重复聚合？比率、转化率和单位成本是否按基础分子/分母重算？
- 单位、百分比和百分点是否正确？事实、推断和建议是否分开？
