# MCP 工具路由

## 总原则

先识别任务类型，再读取当前工具 schema 和动态目录。不要从旧会话记忆参数名、枚举、指标 key、报表 ID、看板 ID 或素材签名。所有调用只读。

## 查询前检查

1. 确认本地绑定仍与当前 MCP 的服务器名、命名空间和核心工具指纹一致。
2. 明确指标、日期、维度、渠道范围、筛选、排序和输出范围；口径遵循 `business-semantics.md`。
3. 业务指标先查 `company_metric_list`，定制报表先查 `unify_spec_report_list`；成本字段按业务语义选择。
4. 检查 schema 的必填参数、分页、日期限制和缓存选项，只传必要字段。

### 报表式“渠道不为线下渠道”查询

当用户说明后台操作为“渠道不为线下渠道”后再拉直接数据时：

1. 先用 `company_metric_list` 确认直接指标，如总有效信息量、上门量、报名量。
2. 用 `unify_table_master` 按 `summary_type: channel` 拉取渠道明细，同时带上消耗和直接指标。
3. 只排除渠道名称严格等于“线下渠道”的行；不要以消耗是否为 0 判断线下，也不要把网络限定字段作为替代。
4. 将所有剩余渠道逐项相加，复核总量与明细相符；非线下零消耗渠道仍保留，并在成本分析中披露其影响。

## 常见路由

### 常规查询

1. 从用户问题解析指标与维度。
2. 若含招生、报名、信息等业务指标，先查 company_metric_list。
3. 从实时 schema 确认渠道维度和筛选能力；默认排除“线下渠道”，不能用消耗为 0 代替分类判断。
4. “含渠道/含线下”分别查询含线下总口径和排除线下的网络口径；“分渠道”按渠道维度保留所有分类并逐项标注。
5. 若问题涉及平台/媒体家族，先做媒体发现，再按 `business-semantics.md` 的默认集合或用户清单过滤；不要用模糊字符串扩展范围。
6. 用 unify_table_master 查询最小字段集。
7. 如需排名或异常线索，再使用相应 AI 工具交叉验证。

### 多院校、省份或区域查询

0. **地域归属闸门（强制）**：先把用户的省份、城市或区域表达标准化，并生成省份↔城市双向候选；城市查询必须反查对应省份命名院校，省份查询必须检查省会/城市命名院校。不得把地域词直接作为工具筛选值，也不得用名称包含、名称前缀或品牌名替代地理归属。
1. 先按院校汇总查询最小字段，完整分页得到当前结果实际出现的院校集合；不要先按“院校+细分维度”拉全国明细，也不要用院校名称前缀代替区域映射。
2. 数据系统没有可靠的省份数据时，先按 skill 中的省份—城市双向映射生成省会及城市候选。省份命名院校、城市命名院校和同一区域的不同品牌都先归一到地理区域，最终只保留后台实际返回的院校及稳定院校 ID。
3. 对省份或区域描述，先得到完整院校列表，再按映射后的院校集合筛选；不得把区域词直接当成筛选值，也不得只用字符串包含判断。
4. 核对当前工具 schema 是否提供 `cids`、院校名、省份、区域或通用 filter 参数。网页前端有列筛选不代表 MCP wrapper 有同名参数；若有，优先使用服务端筛选；若没有，不猜测参数，记录服务端不支持过滤。
5. 过滤能力缺失时，按每个周期只做一次完整的细分维度分页，并在工具编排阶段保留目标院校；结果中列出纳入、排除和无法归属的实际院校。
6. 建立并保留候选清单：用户地域、反向地域别名、实际院校名称、稳定院校 ID、归属状态（纳入/排除/待确认）。在下钻前复核清单，尤其检查“省份+品牌”和“城市+品牌”是否同时出现；无法确认的院校单列，不猜测、不补零。
7. 事业部维度优先尝试值筛选；如果 schema 仅支持 `group_keys` 分组，则按事业部汇总或本地筛选，不把分组当作过滤。

### 异常诊断

1. 用 ai_insight_overview 获取服务侧整体异常和参考日期。
2. 用 unify_ai_insight_summary 或 ai_insight_drill 定位对象和贡献。
3. 用 unify_table_master 拉取同口径底层数据验证。
4. 把“服务标记”“数据事实”“分析推断”分开表述。

### 定制报表

1. 调用 unify_spec_report_list。
2. 按用户指标、维度、报表名称和描述匹配；优先选择能够直接返回目标业务字段的同类报表。
3. 先按院校汇总建立完整候选集合，再检查当前运行 schema 是否有服务端筛选参数。
4. 有筛选参数时，用已核实的 CID/院校/区域/事业部筛选调用 unify_spec_report_run；无筛选参数时，每个周期只做一次完整分页并本地筛选。
5. 取完分页，识别行标签、空白/全量维度、小计和最终合计。
6. 若结果过大、截断或维度/分页/筛选不生效，依次改用同类定制报表、减少字段、减少分组维度，最后拉完整列表后在本地聚合。
7. 记录已验证的报表字段和行结构作为字段画像，但不硬编码报表 ID 或未确认的内部指标含义。

### 素材分析

- 常规曝光、点击、消耗、转化等素材维度数据：unify_table_master。
- 生命周期、健康度、服务侧素材排名：material_dashboard。
- 单素材追查：先取得签名，再 material_detail。
- 轮播内部分析：先取得关系 key，再 material_carousel_info。

## 历史日期与服务快照

AI 洞察类工具可能只返回服务预计算的参考日期或近期快照。若用户明确指定历史日期，不能把当前快照冒充历史结果；优先用 unify_table_master 或对应定制报表。回答中展示实际参考日期。

## 分页、缓存和失败

- 按 schema 的页码、游标或 has_more 取完必要数据。优先使用不超过 50 的小页，除非当前 schema 明确证明更大页稳定；以实际 `detail`/列表内容和 `has_more`/游标为准，不只依赖可能不一致的 `detail_count`。按日期、维度键和指标去重，检测重复页、异常空页和未覆盖维度。
- 出现 `warning`、`truncated` 或 `truncated_json` 时，先减少字段，再减少分组维度，再按日期/媒体/范围拆分并分页重试；`detail_count` 与明细冲突时只视为计数元数据不可靠，继续翻页至空页并披露，不用该字段判断总量。任何未确认的缺口不得补 0。
- 同一查询键的成功分页结果在单次分析中缓存；并发默认控制在 3–4 个请求，失败或限流时只对失败页做有限指数退避重试，不重启整批分页。
- 复杂的学校 × 平台 × 指标分析先拉总览，再对异常对象定向查询；优先在工具编排阶段完成聚合，只把汇总和必要的异常明细传给模型，避免大批量原始返回导致截断或遗漏。
- 只取部分结果时标记范围和截断条件。
- 默认不刷新缓存。强制刷新只用于用户明确要求、验证实时性或排查延迟，并在结果中披露。
- 调用失败时按定制报表备用路径优先改用同类报表，再减小字段或维度范围；仍无法满足时再拉完整列表本地聚合，随后刷新动态目录并检查能力变更。
- 只有定义、时间和维度完全一致时才能换工具；否则说明缺失或请用户确认，不能静默替代。

## 绑定指纹

候选 MCP 至少应同时暴露以下叶子工具名：

- unify_table_master
- company_metric_list
- unify_spec_report_list
- unify_spec_report_run
- ai_insight_overview
- material_dashboard

服务器名可能是“一枝兰数据分析”、data-analysis 或其他名称。名称不是唯一识别依据，工具指纹也不能代替首次用户确认。
